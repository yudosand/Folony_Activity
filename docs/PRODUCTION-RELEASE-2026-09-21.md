## Deployment requirements

Back up the production database, original .env and storage before deployment. Preserve APP_KEY, database/Firebase/mail credentials and private delivery proof files. Set APP_ENV=production, APP_DEBUG=false, APP_URL=https://absent.folony.co.id and FGG_ENVIRONMENT=production. The FGG upstream is https://api.foodukm.com/app/.

Extract into the existing Laravel root with public as document root. Confirm no files were renamed with `_copy`. Clear stale config cache, run migrations and clear application caches using the generated host-locked helper or SSH commands in the guide. Never run key:generate, migrate:fresh or demo seeding on the existing production database.

Migration 000002 deletes only exact autogenerated FGG employee-activity duplicates while preserving source operations and manual entries. Have a database backup before migrations; restoration must account for any new production writes. Rollback is not a blanket migrate:rollback operation.

Staging and production APKs share an application ID. Before switching an existing staging install to production, log out to avoid retaining staging credentials/session state. FGG production accounts must be linked separately.
